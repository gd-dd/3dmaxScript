## 数学和配置

独立重采样检查覆盖 2→5、5→2、非均匀骨段长度、不同参考轴、root/hips 分离、多级父空间、比例、端点旋转变化、中间节点实际变形及取消。零长段、跳父链、无效范围、重复目标、不支持缩放和非法配置有拒绝检查。

自动模式数量相同为逐节点；脊柱/颈/头异数可重采样。预设 schemaVersion 2 保存映射模式，旧 schemaVersion 1 保留逐节点行为。身份歧义不自动绑定。

## Max 2026.3 后台结果

宿主版本为 2026.3（28.3.0.30732），Python 3.11.12。测试使用独立私有 batch，未操作用户当前场景。

- 基础四向：源、预览恢复、写入取消、注入异常及恢复上次烘焙的最大采样矩阵差均为 0；原 Biped 层 current/active 恢复。范围外采样差最大约为 Bone 3.24e-5、Biped 3.05e-4。
- 异数四向：弧长与端点世界旋转误差最大约 1.06e-6 rad，局部骨长误差最大约 0.001852 场景单位（阈值 0.003）；源与事务恢复采样矩阵差均为 0。
- 普通目标：重复烘焙无累积偏移；自动比例约 1.999999714 与手动 2 一致；步长 2 清除范围内原 1.5 帧键、保留范围外键；外部旋转父节点和真实 Euler 时间跨 180°及中点通过。
- 实际 Skin：0–60 帧、61 帧源矩阵保持，源关键帧和 Skin 栈不变；预览/烘焙具有去除根运动后仍存在的非刚性形变；取消、异常、重复与恢复通过。只读测试前后 fixture 文件摘要一致。
- Biped：原有两层及停用层状态纳入验证。必要腿部校正仅本次新层、实际出错侧和完整原生三段腿，最多两次；缺参与者拒绝并回滚，未改 IK 或旧层。

历史宿主报告与后续 UI 修复报告分别保留。当前核心六模块的文件摘要与实际 Skin 宿主报告记录对应，UI 摘要与 UI 修复报告对应；版本声明变化不等于重新执行测试。

## 临时人物屏幕与保存重开

资源为本地临时生成的普通 Bone 骨架、Skin 人物和 0–60 帧动作，没有外部人物下载。源 26 节点、目标 23 节点，脊柱 5→3、颈头 3→2。

专用 Max 中的场景加载、映射和参考姿态由原生准备脚本完成；这些准备步骤不宣称逐个鼠标点击。随后实际操作包括 Skin 权重显示（未编辑权重）、预检、整链编辑、显隐恢复、20 帧预览/恢复、0–60 烘焙、恢复上次烘焙和再次烘焙。20/40/60 帧由原生帧 API 切换，并采集真实窗口截图。

保存结果与预设后重开，源控制器/567 个原始关键帧的可移植基线及全部 61 帧源矩阵保持；重开后源矩阵最大误差 0，Skin 顶点最大误差约 0.0001165 cm，按骨骼名计算的 Skin 权重摘要一致。预设重新加载无待重绑节点，修复后的整链窗口已在可见 Max 复核。

该案例为临时普通 Bone 人物，不代表 Biped 屏幕验收或生产角色验收。

## 发行与限制

公开下载、客户端扫描、安装和运行结果须由 `0.0.1` 发行记录另行确认。历史 `0.0.0` ZIP 摘要不能作为正式附件摘要；清单、标签源码和正式 ZIP 应在发行冻结后核对。

当前未实现 IK、pole vector、末端位置锁定、脚接触或足底稳定。CAT/复杂控制器不作为可写目标支持；其他 Max 版本、更多 Biped 结构、生产角色和大场景性能仍待验证。精确限制见[兼容矩阵](COMPATIBILITY.md)。

从完整源码仓库可运行 `scripts/run_checks.ps1 -Python <带 PySide 的 Python>` 及包校验。宿主与人物 fixture 测试需要专用隔离环境和另行准备的测试资源，不应直接在用户当前 Max 中执行。
