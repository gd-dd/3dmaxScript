# 绑定蒙皮工作台：需求与架构调研

日期：2026-10-30。状态：用户已确认继续使用 Max、操作集中到工具面板；首版完成基础流程与扩展架构，不含完整自动控制器、IK/FK、自动面部绑定。

## 已确认需求

- 统一绑定、权重、蒙皮操作，流程在工具内完成，界面面向创作者。
- 通用骨骼是基础；人形和表情提供专门适配，不把数据结构限定为双足或固定骨数。
- 可继续扩展新功能、算法、骨架模板和导入导出格式。
- 沿用用户提供的图片：当前工具 .lxtool/icon.png；不替换为工具架品牌图片。
- 当前独立仓库 E:/project/LXTools/3dmaxScript；开发阶段不自动提交或发布；2026-10-30 用户另行授权发布 v0.0.2。

## 已确认的范围边界

1. 用户已确认：继续使用 Max，所有新增管理操作集中到工具架面板。
2. 用户已确认：先完成基础流程和扩展架构；不含自动控制器、IK/FK 与自动面部绑定。
3. 若选择 Max：普通 Bones、Dummy/Helper 作为 Skin 影响节点应支持；Biped/CAT 的读取、蒙皮影响与结构编辑需分别探测，不宣称所有控制器均可任意改写。

## 建议分层（宿主无关部分可共用）

- 领域数据：SkeletonGraph、Influence、MeshTopology、SparseWeights、BindPose、MorphChannel、CharacterProfile、OperationReport。
- 命令服务：明确目标、执行前校验、预览差异、提交、执行后读回、恢复；每个命令可独立测试。
- 能力注册：每个功能声明标识、参数 schema、依赖能力、影响范围、是否支持撤销；不把按钮直接绑定脚本字符串。
- 宿主适配：场景查询、主线程修改、Skin/Morpher/控制器接口；UI 和算法模块不能直接访问宿主对象。
- 算法后端：稀疏权重处理与拓扑查询为基础；平滑、镜像、传递和自动赋权各有独立接口。保留原生加速后端，不将尚未实现的求解器显示为可用。
- 任务调度：耗时纯计算离开 UI 线程；宿主场景修改回主线程。任务有取消点、进度和清晰错误。
- 持久化：格式版本、骨骼稳定标识、拓扑签名、单位/轴向/坐标空间、绑定姿态。禁止只按骨骼名称或顶点数量猜测兼容。
- 恢复：权重快照与宿主撤销分开；涉及层级、绑定姿态、多个对象的变更要有一致的失败处理，不能只做一半却报告成功。

## 首版确认流程

准备与诊断 → 骨骼管理 → 绑定 → 权重编辑 → 人形/表情适配 → 变形检查 → 导入导出。

通用骨骼：层级、命名、左右配对、绑定姿态、影响骨骼增减、通用骨链；任意分支和自定义骨数。
权重：顶点/骨骼选择、定值/增减、锁定、归一化、清理微小权重、影响数限制、平滑、镜像、传递、快照、导入导出。
人形：可编辑语义映射、左右校验、脊柱/手指/扭转骨/辅助骨扩展，模板不能覆盖用户骨架。
表情：面部区域、左右配对、面部骨骼与 Morph 通道分开管理，表情预览和重置；保持额外通道，不固定唯一命名标准。

## UI 方向

保留用户图像；左侧流程导航，中间对象/骨骼/权重工作区，右侧当前操作设置，底部任务与检查结果。
始终显示宿主会话、目标模型、当前 Skin/绑定状态、作用范围和选中顶点数。
未连接、无模型、无绑定、操作中、出错等状态有不同提示；不使用无响应的占位按钮。
人形与面部提供专页；通用骨骼入口始终可用。危险修改先展示作用对象与可恢复方式。

## 参考方案与取舍

- mGear：https://github.com/mgear-dev/mgear 。README 声明 MIT，Maya 框架。借鉴组件、模板和可扩展核心；不能直接在 Max 执行。
- SkinningTools：https://github.com/peerke88/SkinningTools 。明确将 Maya 代码独立，尝试 DCC 无关化。借鉴 UI/宿主隔离；仓库涉及多种第三方许可证，未复制其代码。
- ngSkinTools：https://www.ngskintools.com/documentation/v2/api/layers/ 。参考分层、mask、影响节点与镜像映射。不是已接入依赖，不将商业产品当可自由内嵌的库。
- libigl：https://github.com/libigl/libigl 及 https://github.com/libigl/libigl.github.io/blob/docs/docs/tutorial.md 。BBW 可作为后续自动赋权候选，需要体网格/约束和性能验证；不是万能自动绑定，核心与可选依赖许可证应分别审查。
- Max 适配参考：https://github.com/dcc-mcp/dcc-mcp-3dsmax 。关注显式节点引用、主线程写入及读回校验；本轮未安装、未执行远程代码。
- 官方 Skin API：https://help.autodesk.com/cloudhelp/2025/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Modifier-MAXWrapper-and/Modifier-and-SpacewarpModifier/Modifiers/Animation-Modifiers/GUID-0820AA26-920F-434D-A6BC-E8B6B57F54AC.html 。具体功能必须逐项按目标 Max 版本验证。

## 验收要求

用真实宿主/真实几何验证：多分支骨架、超过固定模板骨数、左右骨、无对称模型、退化/断开拓扑、已有 Skin、缺失骨骼、重名骨骼、取消任务、错误恢复和权重往返一致性。
自动测试与实际宿主测试分开记录；界面演示、包校验不算功能完成。图像和资源在正式运行时必须可加载。

## 已落地实现

实际接口与边界以 rig-extension-api.md 为准。当前使用五个嵌入式页签，后台异步等待，Max 主线程执行命令；仅支持开始前取消，无运行中强制中断或进度百分比。权重分层、自动求解器和后台纯计算为扩展方向，未作为本版完成项。生产角色和 Biped/CAT 专项验收仍待后续。
